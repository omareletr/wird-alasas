# Plan: Replace Long-Press Reset with Dedicated Reset Button + Confirmation

## Problem

`TapSurface.tsx` resets the counter for the active dhikr on a 500 ms long-press. This fires silently and irreversibly — a user who holds their finger slightly too long loses all accumulated count for that dhikr with no warning and no undo.

## Chosen Solution

1. **Remove** the long-press reset logic from `TapSurface`.
2. **Add** a small, clearly-labelled reset button positioned just above the progress ring inside `DhikrCard`.
3. **Gate** the reset behind an **inline confirmation step** inside that button: first tap changes it to a brief "Confirm reset?" state; second tap (or timeout cancels it) executes the actual reset.

---

## Implementation Steps

### 1. Remove long-press from `TapSurface.tsx`

- Delete the `LONG_PRESS_MS` constant, `longPressTimer`, `longPressTriggered`, and `cancelLongPress`.
- Remove the `resetCount` selector and the `setTimeout` block in `handlePointerDown`.
- Simplify `handlePointerUp` — it no longer needs the `longPressTriggered` guard.
- Result: `TapSurface` only increments on tap.

### 2. Create `ResetButton` component (`components/counter/ResetButton.tsx`)

A self-contained `"use client"` component that owns the confirmation UX:

```
State: "idle" | "confirming"

- idle     → shows a small RotateCcw icon (Lucide) with `aria-label="Reset counter"`
- confirming → replaces with "Reset?" text + a short 2-3 s auto-cancel timer
              (pressing again confirms; doing nothing or tapping elsewhere cancels)
```

Props:
```ts
interface ResetButtonProps {
  dhikrIndex: DhikrIndex;
}
```

Behaviour:
- First tap → set state to `"confirming"`, start a 2500 ms auto-cancel `setTimeout`.
- Second tap (while confirming) → call `resetCount(dhikrIndex)`, return to `"idle"`.
- Auto-cancel fires → return to `"idle"` with no side-effects.
- The button stops propagation so taps on it don't also increment the counter via `TapSurface`.

Styling: small, muted, positioned above the progress ring — should not draw attention during active counting but be findable when needed.

### 3. Wire `ResetButton` into `DhikrCard.tsx`

- Add `dhikrIndex` prop to `DhikrCard`.
- Place `<ResetButton dhikrIndex={dhikrIndex} />` in the layout just above the `ProgressRing` wrapper `div`.
- Use absolute positioning or a flex column above the ring — confirm exact pixel position visually.

### 4. Pass `dhikrIndex` from `DhikrDeck.tsx` to `DhikrCard`

- `DhikrDeck` already knows `activeIndex`; just forward it: `<DhikrCard entry={entry} count={count} mode={mode} dhikrIndex={activeIndex} />`.

## UX Details

- The `"confirming"` state uses a subtle color/text change (e.g. accent color) with no disruptive modal — keeps the counting flow uninterrupted if the user accidentally taps the button.
- The 2500 ms auto-cancel means even an accidental first tap self-heals.
- The button must call `e.stopPropagation()` on pointer events so it doesn't also trigger the underlying `TapSurface` increment.
