# Plan: Animate DayCompletionBadge entrance/exit

## Problem

`DayCompletionBadge` renders a plain `<span>` that pops into existence abruptly when the completion level changes from `"none"` to `"partial"` (or `"one"`, `"multi"`, `"full"`). There is no enter/exit animation — it just hard-cuts in. Similarly, when the level transitions between states (e.g. partial → full), the pill swaps text with no visual continuity.

## Chosen Animation

**Fade + scale from center, with a gentle spring.**

- `initial`: `{ opacity: 0, scale: 0.75, filter: "blur(4px)" }`
- `animate`: `{ opacity: 1, scale: 1, filter: "blur(0px)" }`
- `exit`: `{ opacity: 0, scale: 0.75, filter: "blur(4px)" }`
- `transition`: `{ type: "spring", stiffness: 400, damping: 22 }`

This is the **"scaleIn"** pattern from Motion design guides — widely recommended for small UI elements like badges, chips, and notification pills. It feels like the badge materialises from nothing rather than snapping in. The slight blur adds a soft, meditative quality consistent with the app's spiritual aesthetic.

The spring config (`stiffness: 400, damping: 22`) lands in the "snappy" range — fast enough to feel responsive and not laggy, but with just enough overshoot to feel alive. The slight blur-in is a subtle polish touch used in premium mobile UIs.

## Implementation Plan

### 1. Refactor `DayCompletionBadge.tsx`

**File:** `components/counter/DayCompletionBadge.tsx`

- Add `"use client"` (already present)
- Import `motion, AnimatePresence` from `"motion/react"`
- Wrap the entire conditional render in `AnimatePresence`
- Convert both `<span>` elements to `motion.span`
- Add a `key` prop tied to the completion level so that transitioning between "partial" and "full" triggers a proper exit + enter crossfade (not just a re-render)
- Apply `initial`, `animate`, `exit`, and `transition` props

**Before:**
```tsx
if (level === "none") return null;

if (level === "full") {
  return (
    <span className="...green...">complete</span>
  );
}

return (
  <span className="...accent...">Partial Completion</span>
);
```

**After:**
```tsx
return (
  <AnimatePresence mode="wait">
    {level !== "none" && (
      <motion.span
        key={level}
        initial={{ opacity: 0, scale: 0.75, filter: "blur(4px)" }}
        animate={{ opacity: 1, scale: 1, filter: "blur(0px)" }}
        exit={{ opacity: 0, scale: 0.75, filter: "blur(4px)" }}
        transition={{ type: "spring", stiffness: 400, damping: 22 }}
        className={level === "full"
          ? "text-[10px] font-sans tracking-wide uppercase text-green-500 border border-green-500/40 px-2 py-0.5 rounded-full inline-block"
          : "text-[10px] font-sans tracking-wide uppercase text-accent border border-accent/40 px-2 py-0.5 rounded-full inline-block"
        }
      >
        {level === "full" ? "complete" : "Partial Completion"}
      </motion.span>
    )}
  </AnimatePresence>
);
```

Notes:
- `mode="wait"` ensures the old pill fades out before the new one fades in when level changes (e.g. partial → full), avoiding a visual overlap.
- The `key={level}` on the `motion.span` is what makes `AnimatePresence` treat each level as a distinct element.
- `inline-block` is added to the className so the `scale` transform doesn't collapse inline box rendering.
- No changes needed to parent components — `DayCompletionBadge` is self-contained.

### 2. No other files need to change

The parent `page.tsx` uses `<DayCompletionBadge />` inside a flex container in the header; the container already handles centering. The animation is fully encapsulated within the badge component.

## Why not CSS-only (tw-animate-css)?

The project uses `tw-animate-css` for simple fade/slide cases. However, this pill needs:
1. A **scale-from-center** effect — not easily done with simple CSS utilities without custom keyframes.
2. A **exit animation** when `level` returns to `"none"` — requires `AnimatePresence` lifecycle management.
3. A **level-change crossfade** (partial ↔ full) — requires keyed `AnimatePresence`.

The Motion library is already imported in `DhikrCard.tsx`, `DhikrDeck.tsx`, and `CompletionOverlay.tsx`, so there is zero bundle cost to using it here.
