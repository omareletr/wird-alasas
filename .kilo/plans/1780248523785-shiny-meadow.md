# UX Fix: Pagination Dots + Swipe Animation

## Current state

**`DhikrDeck.tsx`** renders a single `motion.div` with `drag="x"`. On swipe end it:
1. Snaps back to `x: 0` in 0.1 s via `useAnimation` controls
2. Then updates `activeIndex` in the store

This produces a jarring two-step: snap back → content change with no directional transition. There are also no dots indicating card position.

---

## Fix 1 — Pagination Dots

**Where:** Inside `DhikrDeck.tsx`, below the card area.

**Layout change:** Wrap existing content in a `flex flex-col` container:
- Top: `flex-1 relative overflow-hidden` — card area
- Bottom: dot row (`flex items-center justify-center gap-2 pb-6 shrink-0`)

**Dot rendering:**
```tsx
{ADHKAR.map((_, i) => (
  <motion.div
    key={i}
    className="rounded-full bg-foreground"
    animate={{ opacity: i === activeIndex ? 1 : 0.25 }}
    transition={{ duration: 0.2 }}
    style={{ width: 6, height: 6 }}
  />
))}
```

All dots: uniform circle (6 × 6 px).  
Active dot: full opacity. Inactive: 25% opacity.  
Simple opacity fade on index change.

## Fix 2 — Directional Swipe Animation

**Approach:** Replace the snap-back pattern with `AnimatePresence` + keyed cards.

### State additions (local to `DhikrDeck`)
```ts
const [direction, setDirection] = useState<1 | -1>(1);
// 1  = swiped left  → new card enters from right
// -1 = swiped right → new card enters from left
```

Remove `useAnimation` entirely — it's no longer needed.

### Slide variants
```ts
const slideVariants = {
  enter: (dir: number) => ({ x: dir > 0 ? "100%" : "-100%" }),
  center: { x: 0 },
  exit:  (dir: number) => ({ x: dir > 0 ? "-100%" : "100%" }),
};
```

### AnimatePresence structure
The card area becomes:
```tsx
<AnimatePresence initial={false} custom={direction}>
  <motion.div
    key={activeIndex}
    custom={direction}
    variants={slideVariants}
    initial="enter"
    animate="center"
    exit="exit"
    transition={{ type: "spring", stiffness: 300, damping: 30, mass: 0.8 }}
    drag="x"
    dragConstraints={{ left: 0, right: 0 }}
    dragElastic={0.15}
    dragMomentum={false}
    onDragEnd={handleDragEnd}
    className="absolute inset-0"
    style={{ touchAction: "pan-y" }}
  >
    <TapSurface dhikrIndex={activeIndex}>
      <DhikrCard entry={entry} count={count} mode={mode} />
    </TapSurface>
  </motion.div>
</AnimatePresence>
```

Key points:
- `absolute inset-0` so entering + exiting cards overlap during transition
- `key={activeIndex}` triggers AnimatePresence on every index change
- `custom={direction}` passes direction into variants
- `dragConstraints={{ left: 0, right: 0 }}` + `dragElastic` handles the snap-back on insufficient swipe — **no `controls` needed**

### Updated `handleDragEnd`
```ts
const handleDragEnd = useCallback(
  (_e, info) => {
    const swipedLeft =
      info.offset.x < -SWIPE_OFFSET_THRESHOLD ||
      info.velocity.x < -SWIPE_VELOCITY_THRESHOLD;
    const swipedRight =
      info.offset.x > SWIPE_OFFSET_THRESHOLD ||
      info.velocity.x > SWIPE_VELOCITY_THRESHOLD;

    if (swipedLeft && activeIndex < ADHKAR.length - 1) {
      setDirection(1);
      setActiveIndex((activeIndex + 1) as DhikrIndex);
    } else if (swipedRight && activeIndex > 0) {
      setDirection(-1);
      setActiveIndex((activeIndex - 1) as DhikrIndex);
    }
    // No else: dragConstraints spring the card back to x:0 automatically
  },
  [activeIndex, setActiveIndex]
);
```

React 18 batches the two `setState` calls inside the same event handler, so direction and index update atomically — no risk of the wrong direction being used for the animation.
