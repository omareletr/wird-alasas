# Fix Progress Ring Completion Animation + Color

## Problems

### Bug: pulse fires on card revisit
`ProgressRing` renders the pulse whenever `completed === true`. When the user swipes away from a completed dhikr and comes back, the component remounts with `completed=true`, replaying the pulse animation. `key="complete-pulse"` is static and only prevents duplicates within a single render session, not across remounts.

### Visual: awkward pulse
Animating `strokeWidth` from `2.5×` to `5×` makes the ring thicken outward like a blob rather than ripple cleanly.

### Color: wrong on completion
Both the completed ring stroke and pulse use `var(--foreground)` (white) instead of the app's green (`#22c55e` = Tailwind `green-500`, consistent with `DayCompletionBadge`).

### Speed: ring fill is too fast
`transition={{ duration: 0.15 }}` is too snappy to feel satisfying at the completion moment.

---

## Changes

### 1. `components/counter/DhikrCard.tsx`

- Import `useState` (already imports `useEffect` and `useRef`)
- Add `const [showPulse, setShowPulse] = useState(false)`
- Extend the existing `useEffect` (no dep array): when `count` transitions across `target` (i.e. `count >= target && prevCount.current < target`), set `showPulse = true` and clear it after 700ms via `setTimeout`
- Pass `showPulse={showPulse}` to `<ProgressRing />`

### 2. `components/counter/ProgressRing.tsx`

- Add `showPulse?: boolean` to `ProgressRingProps`
- **Ring stroke color**: change `completed ? "var(--foreground)" : "var(--accent)"` → `completed ? "#22c55e" : "var(--accent)"`
- **Ring transition**: `duration: 0.15` → `duration: 0.3` (more deliberate on the final fill)
- **Pulse render condition**: `{completed && ...}` → `{showPulse && ...}` (fixes the revisit bug)
- **Pulse stroke color**: `"var(--foreground)"` → `"#22c55e"`
- **Pulse animation**: replace the expanding-strokeWidth glow with a scale + opacity ripple:
  - `initial={{ opacity: 0.65, scale: 1 }}`
  - `animate={{ opacity: 0, scale: 1.18 }}`
  - `transition={{ duration: 0.55, ease: "easeOut" }}`
  - Remove the `strokeWidth` animation entirely; keep a fixed `strokeWidth={strokeWidth}`
  - Remove `style={{ rotate: -90 }}` from pulse (it's a full circle, rotation is irrelevant)

# Fix Top Bar and Bottom Dots Spacing

## Problem
- Top bar is too close to the screen edge because `paddingTop: "env(safe-area-inset-top, 20px)"` uses the fallback only when `env()` is unsupported — on desktop/simulator where `safe-area-inset-top` is `0`, no padding is applied.
- Bottom navigation dots use a fixed `pb-6` (24px) with no safe-area-inset-bottom offset, so they hug the screen edge on iPhone.

## Changes

### 1. `app/page.tsx` — line 67
**Old:**
```tsx
style={{ paddingTop: "env(safe-area-inset-top, 20px)" }}
```
**New:**
```tsx
style={{ paddingTop: "calc(env(safe-area-inset-top, 0px) + 20px)" }}
```
Adds 20px of extra breathing room on top of whatever the safe area inset is.

### 2. `components/counter/DhikrDeck.tsx` — line 80
**Old:**
```tsx
<div className="flex items-center justify-center gap-2 pb-6 shrink-0">
```
**New:**
```tsx
<div
  className="flex items-center justify-center gap-2 shrink-0"
  style={{ paddingBottom: "calc(env(safe-area-inset-bottom, 0px) + 24px)" }}
>
```
Replaces the fixed `pb-6` Tailwind class with an inline style that adds 24px on top of the bottom safe area inset.
