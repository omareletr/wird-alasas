# Theme-Switch Circular Ripple Animation

## Approach: View Transitions API + Motion icon spin

**Why this technique:**  
`document.startViewTransition()` is a browser-native API (Chrome/Edge 111+, Safari 18.2+, Firefox 144+) that snapshots the current DOM, applies your changes, then reveals the new state through any CSS animation you define. Pairing it with a `clip-path: circle()` expansion from the tap coordinates is the most visually impressive and widely-copied dark-mode animation pattern of 2024–2025 — zero new dependencies, works with the existing Zustand + class-toggle architecture, and degrades gracefully (instant switch) on unsupported environments.

The icon inside the button gets a Motion `AnimatePresence` rotate+scale swap (you chose "always expand" ripple and "rotate + scale" icon).

---

## Changes

### 1. `components/counter/ThemeToggle.tsx`

**Replace** the plain `onClick={toggleTheme}` handler with a `handleToggle` that:

1. Captures `e.clientX / e.clientY` (the tap coordinates)
2. Sets `--vt-x` / `--vt-y` CSS custom properties on `document.documentElement`
3. Applies the `.dark` class toggle **synchronously** inside the `startViewTransition` callback — this is the key: the browser takes its "new state" snapshot after the callback runs, and since React's `useEffect` (in `ThemeProvider`) is async, we must apply the class directly. `ThemeProvider`'s effect will fire later and find the class already correct (no-op).
4. Then calls `toggleTheme()` to keep the Zustand store in sync
5. Falls back to plain `toggleTheme()` if `startViewTransition` is not available (Safari < 18.2, Firefox < 144)

**Wrap** the icon in `AnimatePresence mode="wait" initial={false}` with a keyed `motion.div`:

```tsx
<AnimatePresence mode="wait" initial={false}>
  <motion.div
    key={theme}
    initial={{ scale: 0.5, rotate: -90, opacity: 0 }}
    animate={{ scale: 1, rotate: 0, opacity: 1 }}
    exit={{ scale: 0.5, rotate: 90, opacity: 0 }}
    transition={{ duration: 0.15, ease: "easeOut" }}
    style={{ display: "flex" }}
  >
    {theme === "dark" ? <Sun size={16} /> : <Moon size={16} />}
  </motion.div>
</AnimatePresence>
```

**Full handler sketch:**

```tsx
const handleToggle = (e: React.MouseEvent<HTMLButtonElement>) => {
  const { clientX: x, clientY: y } = e;
  const newTheme = theme === "dark" ? "light" : "dark";

  if (!document.startViewTransition) {
    toggleTheme();
    return;
  }

  document.documentElement.style.setProperty("--vt-x", `${x}px`);
  document.documentElement.style.setProperty("--vt-y", `${y}px`);

  document.startViewTransition(() => {
    // Apply class synchronously so browser captures correct new colors
    document.documentElement.classList.toggle("dark", newTheme === "dark");
    // Keep store in sync (ThemeProvider effect will be a no-op)
    toggleTheme();
  });
};
```

**New imports needed:** `motion`, `AnimatePresence` from `"motion/react"` (already installed)

### 2. `app/globals.css`

Append at the very end (after the `@layer base` block):

```css
/* ── Theme-switch view transition ──────────────────────────────────────── */

/* Suppress the browser's default cross-fade */
::view-transition-old(root),
::view-transition-new(root) {
  animation: none;
  mix-blend-mode: normal;
}

/* New theme revealed through a circle growing from the tap point */
::view-transition-new(root) {
  clip-path: circle(0 at var(--vt-x, 50%) var(--vt-y, 50%));
  animation: vt-reveal 0.5s cubic-bezier(0.22, 1, 0.36, 1) forwards;
}

@keyframes vt-reveal {
  to {
    clip-path: circle(100vmax at var(--vt-x, 50%) var(--vt-y, 50%));
  }
}

/* Respect reduced motion */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(root),
  ::view-transition-new(root) {
    animation-duration: 0.01ms !important;
  }
}
```

**Why each piece:**
- `animation: none` on old/new suppresses the browser's built-in cross-fade so we own the entire transition
- `clip-path: circle(0 at x y)` → `circle(100vmax at x y)`: starts as a zero-radius point at the tap, grows to fully cover the viewport — `100vmax` guarantees coverage on any screen size or orientation
- `cubic-bezier(0.22, 1, 0.36, 1)` is "ease-out expo" — fast burst at start, smooth deceleration at full coverage
- `var(--vt-x, 50%)` fallback: if the CSS vars aren't set (keyboard activation, or pre-JS), defaults to screen center
- `mix-blend-mode: normal` prevents any blending artifacts from the transition layer sitting above the page

## Browser support matrix

| Browser | Supports `startViewTransition` | Result |
|---|---|---|
| Chrome / Edge 111+ | ✓ | Full circular ripple |
| Safari 18.2+ | ✓ | Full circular ripple |
| Firefox 144+ | ✓ | Full circular ripple |
| Older browsers | ✗ | Instant toggle (graceful fallback) |

Since the app is a PWA and the user population is likely on modern iOS (Safari 18+) and Chrome, this will be the animated path for the vast majority of real users.
