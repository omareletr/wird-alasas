<feature>
  <name>getDevotionalDay — Fajr-based day boundary function</name>
  <files>lib/utils/devotionalDay.ts, lib/utils/devotionalDay.test.ts</files>
  <behavior>
    The function signature is: `getDevotionalDay(now: Date, location: Location): string`

    - Returns YYYY-MM-DD string representing the devotional day for `now` at `location`
    - The devotional day starts at Fajr (Muslim World League calculation method via adhan)
    - If `now >= fajr` for calendar date D → returns D as "YYYY-MM-DD"
    - If `now < fajr` for calendar date D → returns D-1 as "YYYY-MM-DD" (still in yesterday's wird)
    - The function is PURE: accepts `now: Date` as a parameter, never calls `Date.now()` inside
    - Uses `adhan` library: `Coordinates`, `CalculationMethod.MuslimWorldLeague()`, `PrayerTimes`
    - Constructs the adhan date with local time components (`new Date(now.getFullYear(), now.getMonth(), now.getDate())`) — NOT a UTC timestamp — so adhan gets the correct calendar date

    Test cases (London, lat 51.5074, lon -0.1278):
    - After Fajr: `new Date("2026-05-30T06:00:00Z")` → "2026-05-30" (Fajr is ~02:52 UTC in London in May)
    - Before Fajr: `new Date("2026-05-30T01:00:00Z")` → "2026-05-29"
    - DST transition day (UK spring-forward 2026-03-29): `new Date("2026-03-29T10:00:00Z")` → valid YYYY-MM-DD format
    - Year boundary: `new Date("2026-12-31T04:00:00Z")` before Fajr in London → "2026-12-30"

    The `Location` type is exported: `{ latitude: number; longitude: number }`
  </behavior>
