**Important pattern for testing Zustand stores without React:**
```typescript
import { useSessionStore } from "@/lib/store/sessionStore";
// Reset store before each test to avoid cross-test contamination:
beforeEach(() => useSessionStore.setState({ counts: { 0: 0, 1: 0, 2: 0, 3: 0 }, sessionStartedAt: null, mode: "full", activeIndex: 0 }));
// Read state:
const state = useSessionStore.getState();
// Call actions:
state.incrementCount(0);
// Assert:
expect(useSessionStore.getState().counts[0]).toBe(1);
```

For `settingsStore.test.ts`, same pattern — `useSettingsStore.setState(...)` / `useSettingsStore.getState()`.

**Note on `localStorage` in jsdom:** The persist middleware uses localStorage. jsdom provides a localStorage stub. The stores are created with `skipHydration: true` so they won't auto-rehydrate in tests — test state is whatever we set with `setState`. This is correct behavior.
