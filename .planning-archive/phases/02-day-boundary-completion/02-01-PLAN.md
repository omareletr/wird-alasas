<feature>
  <name>classifyDay — completion classification</name>
  <files>lib/utils/completionClassifier.ts, lib/utils/completionClassifier.test.ts</files>
  <behavior>
    - "full" when all 4 dhikr counts >= getTarget(entry, mode) for all ADHKAR entries
    - "partial" when 1-3 dhikr counts >= getTarget(entry, mode) but not all 4
    - "none" when 0 dhikr counts >= getTarget(entry, mode)
    - Mode used is the mode parameter passed to classifyDay (the record's mode), NOT current settings mode

    Test cases:
    - full mode, all counts [200, 200, 100, 100] → "full"
    - full mode, counts [200, 200, 100, 99] → "partial"
    - full mode, counts [200, 0, 0, 0] → "partial"
    - full mode, counts [0, 0, 0, 0] → "none"
    - shortened mode, all counts [20, 20, 10, 10] → "full"
    - shortened mode, counts [20, 20, 10, 9] → "partial"
    - shortened mode, counts [0, 0, 0, 0] → "none"
    - Mode independence: counts [20, 20, 10, 10] with mode "full" → "partial" (20 < 200)
    - Exact boundary: counts [200, 200, 100, 100], mode "full" → "full" (at-target counts)
    - Over-target: counts [250, 200, 100, 100], mode "full" → "full" (tapping past target is allowed)
  </behavior>
  <implementation>
    Export `CompletionLevel = "full" | "partial" | "none"`.

    `classifyDay(counts: Record<DhikrIndex, number>, mode: "full" | "shortened"): CompletionLevel`

    Implementation: filter ADHKAR entries where `counts[entry.index] >= getTarget(entry, mode)`.
    - If completedCount === ADHKAR.length (4) → "full"
    - If completedCount > 0 → "partial"
    - Else → "none"

    Do NOT add a `mode` field to the function signature beyond what's needed — keep the signature minimal.
    Do NOT store CompletionLevel anywhere — it is always derived.
  </implementation>
</feature>
