    Add a second section below the Mode section (separated by a `<hr className="border-white/10" />`):

    ```
    Location
    [status display line]
    [If status is "denied" | "unavailable" | "timeout" | "unsupported" OR location is null:]
      Two number inputs: Latitude (-90 to 90, step 0.0001) and Longitude (-180 to 180, step 0.0001)
      "Save" button → validates range, calls setLocation({ latitude, longitude })
    [If status is "success" OR location is not null:]
      Show current coords: "lat: 21.4225  lon: 39.8262" in monospace white/50
    "Use my location" button → calls retry()
    ```

    Status display:
    - "loading": "Detecting location…" (white/30)
    - "success": "Location detected" (white/50)
    - "denied": "Location access denied. Enter coordinates manually." (white/30)
    - "unavailable" | "timeout": "Location unavailable. Enter coordinates manually." (white/30)
    - "unsupported": "Geolocation not supported. Enter coordinates manually." (white/30)
    - "idle": "" (empty)

    Validation for manual save:
    - Parse lat and lon as floats
    - If isNaN or out of range (lat: -90..90, lon: -180..180), do not call setLocation (silently ignore or show inline text "Invalid coordinates")
    - On valid save, call `setLocation({ latitude: parseFloat(lat), longitude: parseFloat(lon) })`

    Input styling: use `<Input>` from `@/components/ui/input` with `type="number"` `step="0.0001"`. Match existing SettingsSheet monospace aesthetic (`text-sm font-mono`).

    **app/page.tsx — mount hooks + add badge:**

    1. Add imports: `import { useFajrRollover } from "@/lib/hooks/useFajrRollover"` and `import { useGeolocation } from "@/lib/hooks/useGeolocation"` and `import { DayCompletionBadge } from "@/components/counter/DayCompletionBadge"`

    2. Inside `CounterPage` component body, call both hooks:
       ```tsx
       useFajrRollover();
       useGeolocation(); // runs silently; status surfaced in SettingsSheet
       ```
       Do not destructure return values from `useFajrRollover` (it returns void). Destructure `useGeolocation` only if needed — but status is read inside SettingsSheet, not here. Just call it for the side effects.

    3. Add `<DayCompletionBadge />` to the header row between ModeToggle and SettingsSheet:
       ```tsx
       <div className="flex items-center justify-between px-4 shrink-0" ...>
         <ModeToggle />
         <DayCompletionBadge />
         <SettingsSheet />
       </div>
       ```

    Note on useGeolocation in SettingsSheet vs page.tsx: The hook is called in `app/page.tsx` (one instance, provides `retry` + `status` implicitly via settingsStore). SettingsSheet also calls `useGeolocation()` to get the `retry` function and live `status`. Two hook instances is fine — each is lightweight and stateless beyond the `status` state. Alternative: lift the hook to page.tsx and pass `retry` as prop to SettingsSheet — but that complicates the API. Simpler: call it in both, they independently acquire location (the second call may get a cached result with maximumAge:60000). Accept this tradeoff.
